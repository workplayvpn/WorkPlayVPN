# База знаний и обращения — 03.10.2026

## Для пользователя

- Бот → Помощь: база знаний, форма обращения и прямая поддержка.
- Mini App → Нужна помощь: 11 инструкций с поиском, форма и последние 50 обращений.
- Сайт → Частые вопросы / подвал → База знаний: `/help.html`. Публичная страница описывает Basic; Mobile остаётся в Mini App.
- Форма: тема, подписка, сеть, зарегистрированное устройство (необязательно), описание 20–3000 символов.
- Автоматическая диагностика: версия Mini App и общий тип платформы; при выборе устройства — его публичный ID и название. Без ключей, IP, адресов серверов, банковских реквизитов, сырого User-Agent и истории сайтов.
- Изображения пока отправляются отдельно в @workplayvpnteam с номером обращения.
- Статусы: Новое, В работе, Решено, Закрыто. Пользователь видит последний ответ поддержки и получает уведомление в бот, если он не заблокирован.
- Повторная отправка с тем же идентификатором не создаёт второй тикет. Ограничения: максимум 3 новых обращения за 10 минут и 5 открытых на аккаунт.

## Что меняется

Миграция `d07a63e8b291` после `c93f821a70d4` создаёт `support_tickets`.
Новые endpoints `/mini-app/support/tickets` требуют подписанную авторизацию Telegram и возвращают только собственные обращения.
`/internal/support/*` защищены внутренним секретом, пользовательские Mini App credentials к ним не подходят.
Команды поддержки в боте проверяют числовой ID владельца и разрешены только в личном чате.
Платежи, тарифы, реферальный учёт и VPN-маршруты не меняются. Новые серверы и платные внешние сервисы не нужны.

## Уведомления

Бот проверяет сохранённую очередь каждые 30 секунд. После успешной доставки записывает подтверждение.
При сетевой ошибке очередь остаётся для повторной попытки. Возможен повтор уведомления, если Telegram доставил сообщение, а подтверждение в backend не дошло; номер обращения не меняется.
Если пользователь заблокировал бота, ответ остаётся в Mini App, а недоставляемое уведомление не блокирует очередь других пользователей.
Если владелец заблокировал бота или указан неверный ID, новая заявка остаётся в базе; уведомления будут повторяться после исправления настроек.
При SUPPORT_ADMIN_TELEGRAM_ID=0 уведомления и административные команды выключены. При установке обязательно настроить владельца и убедиться, что он нажал /start.

## Проверка на ноутбуке

```powershell
docker compose --profile testing run --rm tests
if ($LASTEXITCODE -ne 0) { throw "Тесты backend не прошли" }
$botSource = Join-Path (Get-Location).Path "bot"
docker compose run --rm --no-deps --pull never --volume "${botSource}:/app:ro" --entrypoint python bot -m unittest discover -s tests -v
if ($LASTEXITCODE -ne 0) { throw "Тесты бота не прошли" }
git -c core.whitespace=cr-at-eol diff --check
```

В тесты включены проверка чужого устройства/обращений, авторизация, повторные отправки, лимиты, безопасный состав диагностики, сохранение ответа при смене статуса и гонка подтверждения уведомления. Отдельный PostgreSQL-тест проверяет параллельную отправку одного обращения.

## Установка на сервере

Сначала резервная копия базы. Сохранить локальные изменения `caddy/Caddyfile`.
Обновить git, собрать backend и bot, затем выполнить миграцию, проверить head, перезапустить backend и bot.

```bash
docker compose build backend bot &&
docker compose run --rm --no-deps backend alembic upgrade head &&
docker compose run --rm --no-deps backend alembic current &&
docker compose up -d --no-deps --wait backend &&
docker compose up -d --no-deps bot
```

В личном чате с Work&PlayVPN отправить `/start`, затем `/support_id`. На сервере подставить полученный ID:

```bash
python3 ops/configure_support.py --telegram-id ЧИСЛОВОЙ_ID --apply &&
docker compose up -d --no-deps --force-recreate bot
```

Скрипт сохраняет копию `.env` с правами 600, меняет только SUPPORT_ADMIN_TELEGRAM_ID, не печатает секреты.

## Работа владельца в боте

```text
/tickets
/ticket НОМЕР
/ticket_status НОМЕР in_progress Проверяем подключение, спасибо за описание.
/ticket_status НОМЕР resolved Обновите подписку в Happ и переподключитесь.
/ticket_status НОМЕР closed
```

Смена статуса без текста сохраняет предыдущий ответ. Новая фраза заменяет последний ответ; это очередь обращений, а не полноценный многосообщенческий чат.
Пользователю отправляются только статус и ответ — служебные команды владельца не пересылаются.

## После установки

Проверить `/health`, Alembic head, состояния backend/bot и `/help.html` (200).
Закрыть Mini App полностью и открыть снова: CSS/JS версия `20261003-2`.
Создать одно тестовое обращение с описанием «Проверка формы поддержки, реальной проблемы нет», получить уведомление, ответить через /ticket_status, проверить статус/ответ в Mini App и уведомление пользователя. Не использовать реальные ключи или банковские данные.
