# Work&PlayVPN — ключи и устройства в Mini App

> Обновление от 2026-10-04: эта инструкция заменена файлом
> `docs/miniapp-crypt5-fix-2026-10-04.md`. Используйте новый архив и команды из него.
> Первоначальный вариант ошибочно копировал URL страницы инструкции.
> В исправленном варианте копирование, полный ключ и QR содержат `happ://crypt5/...`.

Архив рассчитан на текущую main после 9c1d1f7 (Fix help key login in Telegram Web Mini App).
Распаковать в корень WorkPlayVPN с заменой файлов. В архиве только 13 изменённых/новых файлов.

## Что изменилось

- В карточке Basic/Mobile появились «Скопировать ключ», «QR-код», «Показать полный ключ».
- Перед получением ключа выбирается уже подключённое устройство. Для Basic и автоматического Mobile используются соответствующие индивидуальные ссылки устройства. Для старого Mobile без автомаршрутизации сохранён общий ключ подписки.
- QR создаётся нашим backend и содержит ровно ту ссылку, которую показывает/копирует окно. Чёрный код на белом фоне, свободная рамка для сканирования. Сторонние QR-сервисы не используются.
- Если устройств ещё нет, окно предлагает перейти к существующему подключению через Happ. Просмотр ключа сам не создаёт устройство, не занимает слот и не оформляет оплату.
- Полный ключ, QR и выбранное устройство очищаются при закрытии окна. Поздний ответ запроса не открывает закрытое окно заново. Ответ нового API не кэшируется.
- Копирование показывает «Скопировано ✓». Если буфер обмена недоступен, открывается поле для ручного копирования.
- Свои SVG-иллюстрации: телефон, планшет, ноутбук, компьютер, телевизор, универсальное устройство/свободный слот. Тип определяется по модели/ОС/названию. Неизвестная модель получает универсальный значок.
- Бирюзовые рамки, плавное появление окон, подсветка карточек, поддержка уменьшения анимации в настройках устройства.
- Встроенная кнопка Telegram «Назад» сначала закрывает открытое окно и оставляет пользователя в карточке подписки.

Ключ подключения VPN и персональный ключ входа в помощь — разные сущности.
Тарифы, оплаты, общий лимит устройств, маршрутизация, ключи помощи и поддержка сохранены.
Миграций БД и новых переменных окружения нет. Добавлена зависимость backend qrcode==8.2 (без Pillow).

## 1. Проверка на Windows / PowerShell

Сначала положите ZIP в корень проекта, где находится docker-compose.yml.

```powershell
$ErrorActionPreference = "Stop"
$archivePath = (Resolve-Path -LiteralPath .\WorkPlayVPN-miniapp-key-design-2026-10-03.zip).Path
Expand-Archive -LiteralPath $archivePath -DestinationPath . -Force -ErrorAction Stop

$backendSource = Join-Path (Get-Location).Path "backend"
$opsSource = Join-Path (Get-Location).Path "ops"
# --build нужен: в образ backend/tests добавляется qrcode.
docker compose --profile testing run --build --rm --volume "${backendSource}:/app:ro" --volume "${opsSource}:/ops:ro" tests
if ($LASTEXITCODE -ne 0) { throw "Тесты backend не прошли" }

git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw "Проверка изменений не прошла" }
```

Если сборка оборвалась при обращении к Docker Hub, тесты ещё не запускались. Повторите сборку после восстановления доступа; не переходите к коммиту до успешных тестов.

## 2. Коммит — после успешной проверки

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$archive = [System.IO.Compression.ZipFile]::OpenRead($archivePath)
try {
    $patchFiles = @($archive.Entries | Where-Object { $_.Name -ne "" } | ForEach-Object { $_.FullName })
}
finally { $archive.Dispose() }

git add -- $patchFiles
if ($LASTEXITCODE -ne 0) { throw "Не удалось добавить файлы" }
git -c core.whitespace=cr-at-eol diff --cached --check
if ($LASTEXITCODE -ne 0) { throw "Проверка изменений не прошла" }
git diff --cached --stat
# Проверьте, что в списке именно файлы этого обновления.
git commit -m "Add Mini App key actions and illustrated devices"
if ($LASTEXITCODE -ne 0) { throw "Коммит не создан" }
git push origin main
if ($LASTEXITCODE -ne 0) { throw "Не удалось отправить коммит" }
git log -1 --oneline
```

## 4. Проверка в Telegram

1. Откройте Basic → «Показать полный ключ» → выберите устройство. Проверьте название устройства и Basic в заголовке. Закройте окно: должна остаться карточка Basic.
2. «Скопировать ключ» → то же устройство. Проверьте «Скопировано ✓». Вставьте в поле ввода Happ и убедитесь, что ссылка целиком совпадает с полем полного ключа. Не публикуйте ключ/QR.
3. «QR-код» → то же устройство. Отсканируйте в Happ на этом устройстве. Используйте другое своё устройство только с его собственным ключом, чтобы не дублировать идентификатор устройства.
4. Повторите для Mobile. Ссылка должна относиться к Mobile (в пилоте — /auto/routed/device/…), а не Basic (/device/…). Для старого Mobile окно показывает «Ключ подписки Mobile».
5. Проверьте иллюстрации iPhone/iPad, Windows/ноутбука/TV по вашим реальным метаданным. Если модель ещё не сообщена Happ, допустим универсальный значок.
6. Проверьте крестик, нижнюю кнопку «Закрыть», нажатие на фон и встроенную кнопку Telegram «Назад». Фоновая страница должна снова прокручиваться.
7. Проверьте на телефоне и в Telegram Web: кнопки и длинные имена не должны выходить за экран. Проверьте светлую тему, если используете её.
8. Аккаунт без устройств: кнопки ключа предлагают сначала подключить устройство; просмотр не создаёт новый слот.
9. Проверьте существующее подключение через Happ, продление, добавление лимита, смену региона, вход/выход из помощи.
