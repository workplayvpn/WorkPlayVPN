# Улучшение светлой темы Mini App

Патч поверх установленного раздела «Подарки». Меняются только index.html и добавляется light-theme.css. Новых зависимостей, изменений backend, БД, платежей или миграций нет.

## Что изменилось

- «Подарки»: светлая мятная карточка, читаемый заголовок, описание и стрелка. Внутри раздела адаптированы карточки, цены, статусы, поля ввода, код, выбранные вкладки и сообщения ошибок.
- Белые поверхности отделены от фона более заметными границами. Тени карточек заметно легче.
- Убраны полосатые заливки светлых карточек Basic/Mobile, ослаблены декоративные круги. Mobile сохраняет мягкую янтарную метку.
- Основные кнопки имеют белый текст на фирменном бирюзовом фоне; вторичные — белую поверхность с границей.
- Таблица сравнения получила светлый заголовок и чередование фона строк. Улучшены подсказки, панели и поля.
- Все селекторы нового файла ограничены :root[data-theme="light"]. В тёмной теме этот файл не применяет правил. Переключение темы Telegram продолжает работать.

Фон и системная шапка Telegram согласованы с существующей палитрой #f2f6f5. Макет, размеры и навигация сохранены, чтобы светлая и тёмная темы оставались одинаково удобными.

## На ноутбуке — распаковка и проверка

В корне проекта, PowerShell. Сначала сохрани предыдущие изменения в Git, чтобы можно было восстановить index.html.

```powershell
$ErrorActionPreference = "Stop"
$archivePath = (Resolve-Path -LiteralPath .\WorkPlayVPN-light-theme-2026-10-05.zip).Path
Expand-Archive -LiteralPath $archivePath -DestinationPath . -Force -ErrorAction Stop

git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw "Проверка изменений не прошла" }
Select-String -LiteralPath .\caddy\mini-app\index.html -Pattern 'light-theme.css'
git diff -- caddy/mini-app/index.html
```

В index.html должна появиться ссылка /app/assets/light-theme.css?v=20261005-1 после остальных CSS. Если Git показывает большие посторонние изменения index.html, остановись и пришли diff: не заменяй более свежую разметку старой. В обычном случае diff содержит только добавленную ссылку.

Локально проверены структура CSS, ограничение каждого селектора светлой темой и контрастность основных цветов (не менее 4,5:1 для проверенных сочетаний). Это не полный автоматический аудит доступности. Живую отрисовку в iOS Telegram нужно проверить после обновления; локального браузера для скриншотов в этой среде нет. Backend-тесты для изменения стилей не требуются.

## Коммит и отправка

```powershell
git add -- caddy/mini-app/index.html caddy/mini-app/assets/light-theme.css docs/light-theme-2026-10-05.md
if ($LASTEXITCODE -ne 0) { throw "Не удалось добавить файлы" }
git -c core.whitespace=cr-at-eol diff --cached --check
if ($LASTEXITCODE -ne 0) { throw "Проверка staged изменений не прошла" }
git diff --cached --stat
git commit -m "Improve Mini App light theme contrast and card surfaces"
if ($LASTEXITCODE -ne 0) { throw "Коммит не создан; проверь git log -1, возможно он уже был создан" }
git push origin main
if ($LASTEXITCODE -ne 0) { throw "Не удалось отправить коммит" }
```

## Сервер

Для текущей схемы, где Mini App подключён в Caddy через bind-mount:

```bash
cd /opt/workplayvpn
git pull --ff-only origin main
```

Статика обновляется без пересборки backend, бота и без миграции. Если у тебя используется образ со встроенной статикой, обнови его по своей текущей схеме.

Полностью закрой Mini App и открой заново. Новый CSS имеет отдельную версию, HTML отдаётся без кеширования.

## Проверка в Telegram

1. В светлой теме проверить главную: «Подарки» читается, тени не образуют серую подложку, белые карточки различимы.
2. Каталог Basic/Mobile, таблица сравнения и «Мои подписки»: контрастный текст, спокойные заливки, понятные кнопки и метки.
3. Подарки: купить, активировать, мои подарки, поле кода и ошибки — все поверхности светлые, текст виден. Не нужно совершать реальную оплату ради проверки дизайна.
4. Рефералы, помощь, устройства и окна с ключом/QR: без нечитабельных полей или подписей. QR остаётся исходным, его содержимое патч не меняет.
5. Переключить Telegram на тёмную тему при открытом Mini App и проверить прежний вид. Затем обратно на светлую.

Для отката верни предыдущую версию только index.html (убрать добавленный link) и отправь её в Git. Backend и БД откатывать не нужно.
