# Вход в центр помощи по ключу

## Использование

Бот → «Помощь» выдаёт персональный ключ `tg-…` и кнопку копирования. Он открывает только центр помощи. Выдача ключа через бот разрешена в личном чате; в Mini App ключ можно показать на экране входа после авторизации Telegram.
Ключ вводится вручную на `/help.html`, в базе знаний Mini App и в форме обращения. Вход сохраняется на один час отдельно для каждого домена; кнопка «Выйти» удаляет cookie.
Истёкшая подписка не закрывает помощь. Смена версии ключа подписки инвалидирует прежний ключ помощи и сессии; отключённый аккаунт не проходит проверку.

## Защита

Ключ помощи имеет отдельную HMAC-подпись (128 бит), зависит от пользователя и версии subscription_tokens, не совпадает с ключом VPN и не даёт доступ к VPN. Пароли/ключи VPN в форму не вводятся.
Сессионный cookie Secure, HttpOnly, SameSite=Strict, без ключа или VPN-токена. Клиент не сохраняет ключ в URL, localStorage или sessionStorage.
Инструкции читаются через защищённые backend endpoints. В Mini App чтение и создание обращений требуют одновременно ключ помощи и подписанную авторизацию Telegram; чужой ключ отклоняется. Публичная страница не даёт доступа к истории обращений и описывает Basic.
Данные знаний перенесены из двух публичных JSON-файлов в backend/app/data/knowledge.json. Старые статические JSON необходимо удалить из Git, чтобы их нельзя было скачать напрямую.
Вход ограничен 30 попытками в минуту на адрес клиента в пределах процесса backend; неудачные попытки не раскрывают, существует ли аккаунт.

## Установка на ноутбуке

Распаковать архив в корень проекта. Удалить из репозитория:

```powershell
git rm -- caddy/mini-app/assets/knowledge.json caddy/site/assets/knowledge.json
```

Запустить тесты backend через профиль testing и тесты бота с локальным bind mount, затем добавить только файлы архива и два удаления, проверить git diff --cached --check, commit и push.

## Установка на сервере

Сохранить локальное изменение caddy/Caddyfile с bot-forma.ru. Перед git pull убедиться, что нет других конфликтующих изменений.
После получения коммита собрать backend и bot, перезапустить backend, затем bot:

```bash
docker compose build backend bot &&
docker compose up -d --no-deps --wait backend &&
docker compose up -d --no-deps bot
```

Миграция не требуется. Затем добавляется только маршрутизация API центра помощи на публичном домене. Скрипт не заменяет Caddyfile целиком, сохраняет прочие домены, делает резервную копию и при повторном запуске ничего не меняет.

```bash
python3 ops/configure_help_access.py --apply &&
docker compose exec -T caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile &&
docker compose exec -T caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Если валидация конфигурации не прошла, Caddy не перезагружать. Вернуть Caddyfile из созданной копии и сообщить текст ошибки.

## Проверка после установки

- `/health`: healthy.
- Бот в личном чате → «Помощь»: ключ и кнопка копирования.
- Сайт `/help.html`, Mini App → «Помощь» и прямая форма: экран ввода ключа.
- Неверный ключ не открывает содержимое; правильный открывает его, выход снова закрывает.
- Без cookie `/help-access/knowledge`, `/mini-app/support/knowledge` и история обращений недоступны (403; без Telegram возможен 401).
- `/assets/knowledge.json` и `/app/assets/knowledge.json` не выдают инструкции.
- В Mini App чужой ключ не открывает страницу даже при действительной авторизации Telegram.
- Тестовая заявка создаётся после входа; уведомление владельцу и ответ пользователю продолжают работать.

## Локальные проверки

20 проверок backend: ключи, подписи, срок сессии, выход, смена версии, отключённый пользователь, чужой аккаунт, Telegram, CSRF, rate limit и существующий учёт обращений.
31 проверка бота: копирование, обработка сбоя получения ключа, запрет выдачи в группе и существующие пользовательские сценарии.
Проверка интерфейсов в браузере: закрытое содержимое, неверный ключ, выдача собственного ключа, ручной вход, выход, очистка карточек, узкий экран и светлая тема.
