# Регистрация устройств по общей ссылке Happ

Основа: 88d835f. Один общий crypt5-ключ для Basic и один для Mobile сохраняются.

## Причина и поведение

Раньше `/sub/<token>` и общая Mobile JSON-подписка отдавали credential первого активного устройства. Импорт на другом телефоне не создавал запись устройства и не проверял новый слот.

После включения исправления сервер использует `X-HWID`, переданный Happ, для выбора/регистрации устройства владельца подписки. В БД хранится только HMAC идентификатора. Новое устройство получает собственные Basic/Mobile credentials через существующий процесс настройки Xray. Данные модели и ОС сохраняются в той же транзакции, что и новая запись. Обновление и использование обеих подписок одним HWID не создают дубль. Общий лимит учитывает оплаченные дополнительные слоты. Создание устройств и удаление сериализуются блокировкой строки пользователя PostgreSQL.

Исправление распространяется на обычную Basic/Mobile подписку и на оба общих `/sub/auto/...` маршрута. При включённом режиме запрос без HWID получает 403 и не получает чужую конфигурацию; при заполненном лимите новый HWID получает 409. Действующее устройство может обновлять подписку при заполненном лимите. Удалённый HWID не регистрируется автоматически заново; для повторного добавления нужно создать новое устройство через кабинет и импортировать его инструкцию. Старая ссылка с ID устройства может привязать только собственное активное устройство, которое ещё не привязано к другому HWID.

Старые неопознанные записи не присваиваются новому телефону наугад. Если старое устройство ещё не имеет HWID, импортируйте его существующую индивидуальную инструкцию из меню подключения устройства, чтобы привязать запись, либо удалите неиспользуемую запись. Общие кнопки ключа/QR остаются без выбора устройства.

Копирование ключа в Mini App само по себе слот не расходует: запись появляется при запросе конфигурации из Happ. Для обновления списка нажмите обновление Mini App.

## Границы защиты

HWID приходит от клиента и не является аппаратной аттестацией. Это учёт установок Happ и ограничение выдачи конфигураций, а не абсолютная защита от подделки HWID или копирования уже выданных VLESS credentials. crypt5 шифрует ссылку подписки, а не делает её непередаваемой.

Уже импортированный до исправления конфиг сохраняет старый UUID до обновления/отзыва. После установки получатель отправленной ссылки должен обновить подписку в Happ: тогда для него создастся собственная запись. Если прежний UUID уже распространяли вне Happ, для полного отзыва потребуется отдельно заменить эти credentials на ноде и обновить действующие устройства. Этот архив не отзывает доступ существующим устройствам массово.

Нет миграций и новых backend-зависимостей. Регистрация по умолчанию выключена для контролируемой установки; скрипт ниже включает её в `environment` backend в серверном override. Он сохраняет существующие настройки БД, TLS и токены, создаёт резервную копию override и не меняет воркеры.

## Windows: распаковка и тесты

Из корня проекта:

```powershell
$ErrorActionPreference = "Stop"
$archivePath = (Resolve-Path -LiteralPath .\WorkPlayVPN-happ-device-registration-2026-10-04.zip).Path
Expand-Archive -LiteralPath $archivePath -DestinationPath . -Force -ErrorAction Stop
$backendSource = Join-Path (Get-Location).Path "backend"
$opsSource = Join-Path (Get-Location).Path "ops"
docker compose --profile testing run --rm --pull never --volume "${backendSource}:/app:ro" --volume "${opsSource}:/ops:ro" tests
if ($LASTEXITCODE -ne 0) { throw "Тесты backend не прошли" }
git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw "Проверка изменений не прошла" }
```

Локально у автора проверены 43 теста: новая регистрация, маршруты подписок, прежние ключи и метаданные. Две дополнительные проверки одновременных импортов требуют PostgreSQL и выполняются в вашем тестовом контейнере. Полный backend-набор также нужно выполнить этой командой.

## Коммит после успешных тестов

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$archive = [System.IO.Compression.ZipFile]::OpenRead($archivePath)
try { $patchFiles = @($archive.Entries | Where-Object { $_.Name -ne "" } | ForEach-Object { $_.FullName }) }
finally { $archive.Dispose() }
git add -- $patchFiles
if ($LASTEXITCODE -ne 0) { throw "Не удалось добавить файлы" }
git -c core.whitespace=cr-at-eol diff --cached --check
if ($LASTEXITCODE -ne 0) { throw "Проверка изменений не прошла" }
git diff --cached --stat
git commit -m "Register Happ devices from shared subscription keys"
if ($LASTEXITCODE -ne 0) { throw "Коммит не создан" }
git push origin main
if ($LASTEXITCODE -ne 0) { throw "Не удалось отправить коммит" }
```

## Сервер: обязательно включить регистрацию

```bash
set -e
cd /opt/workplayvpn
git pull --ff-only origin main
docker compose build backend
python3 ops/configure_happ_device_registration.py
docker compose up -d --no-deps --force-recreate backend
docker compose exec -T backend python -c 'from app.core.config import settings; print("Happ registration enabled:", settings.happ_account_device_registration_enabled)'
docker compose ps backend
docker compose logs --tail 30 backend
```

Вывод настройки должен быть `True`, backend должен стать healthy. Миграции запускать не нужно. PyYAML на сервере ранее уже был доступен.

## Реальная проверка

1. На своём старом устройстве обновить подписку в Happ и проверить работу.
2. Получателю отправленной ссылки обновить подписку в Happ.
3. Обновить Mini App: новая карточка должна появиться, счётчик увеличиться на один.
4. Повторить обновление Happ: карточка и количество не должны дублироваться.
5. На одном устройстве импортировать Basic и Mobile: второй слот не расходуется.
6. При заполненном лимите новый телефон не должен получать конфигурацию.
7. Удаление зарегистрированного устройства отзывает его собственные credentials; другое устройство сохраняет доступ. Уже открытые соединения могут завершаться по правилам Xray.

Если ваша версия Happ не передаёт HWID, не включайте массово диагностику с реальными ссылками в переписке. Обновите Happ; при необходимости исследуйте только имена заголовков и обезличенные идентификаторы.

## Временный откат режима

```bash
python3 ops/configure_happ_device_registration.py --disable
docker compose up -d --no-deps --force-recreate backend
```

Это возвращает прежнее поведение общей подписки, включая прежний недостаток учёта. Записи новых устройств сохраняются. Не используйте отключённый режим как постоянную защиту лимита.
