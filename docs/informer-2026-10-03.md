# Личный информатор Work&PlayVPN

База патча: main 7344fc7. Бот: @WorkPlayVPNInformerBot. Получатель: только
INFORMER_OWNER_TELEGRAM_ID (по умолчанию 2027613435). Нажмите «Запустить»
в отдельном боте до проверки доставки. Токен не присылайте в чат и не коммитьте.

## Что сделано

- Подписки и продления: Telegram ID, @username при наличии, ссылка на профиль,
  индивидуальный ключ **помощи**, Basic/Mobile, название тарифа, оплаченный срок
  в днях, окончание подписки по Москве, сумма и номер платежа.
- Дополнительные устройства: количество купленных слотов и новый общий лимит.
- Тестовые платежи отмечены отдельно. Бесплатные триалы не проходят через этот
  платёжный обработчик и в этой версии не присылаются. Отдельной надписи «первичная
  покупка» или «продление» пока нет: общий заголовок «оформлена / продлена».
- Событие создаётся в одной транзакции с успешной выдачей покупки. Для подписок
  это успешное завершение существующего fulfillment, включая сообщение клиенту;
  для слотов — транзакция подтверждения оплаты и прибавления лимита.
- Очередь в PostgreSQL, уникальность по платежу, повторная доставка с задержкой
  до часа. Ошибка Telegram не повторяет покупку и не увеличивает лимит устройств.
- Ключ вычисляется при отправке из текущей версии токена и не хранится в очереди.
- Исторические покупки до установки автоматически не рассылаются.
- Бот не принимает команды и не отвечает клиентам. Антифрод будет отдельным этапом.

Telegram не предоставляет идемпотентный sendMessage. При сбое после принятия
сообщения Telegram, но до фиксации результата в БД, возможен повтор; номер платежа
позволяет его распознать. Доставка проверяется с реальным токеном на сервере.

## Локальная установка и проверки (PowerShell)

Сохраните ZIP в корень WorkPlayVPN. Он содержит только изменённые/новые файлы
и не заменяет docker-compose.yml или Caddyfile. Не меняйте серверные настройки CDN.

```powershell
Expand-Archive -LiteralPath .\WorkPlayVPN-informer-2026-10-03.zip -DestinationPath . -Force -ErrorAction Stop
docker compose --profile testing run --build --rm tests
if ($LASTEXITCODE -ne 0) { throw "Backend tests failed" }
git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw "Diff check failed" }
```

Для Docker tests перед запуском используйте тот же тестовый PostgreSQL и команды,
которые применялись ранее. Если локальный сервис tests содержит изменённую команду,
сначала примените миграции к ТЕСТОВОЙ БД. Не выполняйте очистку схемы в production.

После успешных тестов добавьте именно файлы из ZIP, проверьте staged diff,
создайте коммит и отправьте в main. У скрипта configure_informer_compose.py есть
режим проверки без --apply. Серверные .env и docker-compose.yml не коммитьте.

## Установка на сервере

Из /opt/workplayvpn после загрузки коммита:

```bash
git pull --ff-only
python3 ops/configure_informer_compose.py --apply
python3 ops/configure_informer.py
```

Последняя команда попросит токен нового бота скрытым вводом и добавит его в
приватный .env. Не вставляйте токен в командную строку. Скрипт Compose добавляет
informer-worker, наследующий существующие настройки payment-fulfillment-worker:
сохраняет реальную серверную DATABASE_URL, TLS-сертификаты, сети и Telegram-прокси.
Также передаёт PAYMENT_MODE и ROBOKASSA_IS_TEST обработчику выдачи, чтобы корректно
отмечать тестовые оплаты. Скрипт не изменяет остальные сервисы и домены.

```bash
docker compose config --quiet
docker compose build backend payment-fulfillment-worker informer-worker
docker compose run --rm --no-deps backend alembic upgrade head
docker compose run --rm --no-deps informer-worker python -m app.workers.informer --test
```

Не продолжайте, если любая команда завершилась ошибкой. После получения тестового
сообщения:

```bash
docker compose up -d backend payment-fulfillment-worker informer-worker
docker compose ps backend payment-fulfillment-worker informer-worker
docker compose logs --tail=30 informer-worker
```

Проверьте новый тестовый платёж подписки и пакет слотов: клиент получает покупку,
владелец — соответствующее уведомление. Повторный webhook не должен создавать
ещё одно событие. Не делайте реальную покупку лишь ради проверки.

Отключение отправки: docker compose stop informer-worker. Очередь сохраняется;
при повторном запуске сообщения будут доставлены. Не удаляйте таблицу очереди.

## Проверки при подготовке

Локально пройдены 11 изолированных тестов очереди/доставки/патчера Compose,
проверена единственная Alembic head e190ad62bc41 и diff --check.
В тест покупок слотов добавлена PostgreSQL-проверка уникальности уведомления и лимита.
Полный backend suite с PostgreSQL и реальная доставка Telegram здесь не запускались;
их нужно выполнить описанными выше командами до включения.
