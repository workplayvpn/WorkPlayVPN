# Work&PlayVPN: реферальная программа

## Реализовано

- Ставка 15% от фактически подтверждённой рублёвой покупки/продления Basic и Mobile; округление до копейки.
- Привязка только нового пользователя при первом `/start ref_<code>`. Существующий аккаунт не перепривязывается. Самоприглашение, неизвестный код и приглашение отключённого аккаунта не учитываются.
- Непрозрачный стабильный код ссылки; чужие Telegram ID и контакты приглашённых в Mini App не раскрываются.
- Начисление в одной транзакции с Payment, Fulfillment и активацией. Уникальная комиссия на payment_id, блокировка кошелька, без повторного начисления при повторном webhook. Исторические платежи не пересчитываются.
- Пробные периоды, тестовые платежи, дополнительные слоты и валюты кроме RUB не учитываются.
- Денежные суммы — целые копейки. Минимум заявки 50 000 копеек (500 ₽). Одна открытая заявка на пользователя, резервирование, идемпотентность, отмена до обработки.
- История последних 100 начислений и заявок, общие счётчики приглашений и оплативших. Баланс учитывает всю историю.
- Выплаты вручную на согласованную личную карту. Публичного API администратора нет. База программы не содержит PAN/CVV/SMS-кодов. Код сам не отправляет деньги и не уведомляет участников сообщениями.
- Сайт: подробный блок, векторная иллюстрация, лёгкая CSS-анимация с поддержкой reduced-motion, отдельные условия программы. Mobile на публичных страницах не упоминается.

## Не автоматизировано

Банковский перевод, проверка получателя и его налогового статуса, обязательные удержания/отчётность, а также фактический возврат покупателю выполняются отдельно. Баланс и заявки не заменяют бухгалтерский учёт. Перед реальными выплатами необходимо определить оформление выплат ИП на НПД. 15% — начисленное вознаграждение; применимые удержания разъясняются получателю до перевода.

Провайдеры проекта пока не имеют обработчиков уведомлений о возвратах. После подтверждённого возврата оператор обязан запустить команду корректировки ниже. Команда сама не возвращает покупателю деньги и не отменяет подписку. При возврате после выплаты возможен отрицательный баланс, который покрывается последующими начислениями. До первой реальной оплаты это можно безопасно проверить в тестовом окружении.

## Проверки

Локально: 12 тестов учёта денег на изолированной SQLite, 23 теста бота, запросы без авторизации, схема API, JavaScript, селекторы Mini App, отображение копеек и тело заявки, ссылки сайта и SVG. Полный Docker-прогон PostgreSQL обязателен перед установкой; в нём добавлены отдельные тесты параллельных webhook и заявок, атомарности активации, привязки и доступа.

## Установка после успешных проверок

1. Проверить резервную копию production-БД перед миграцией.
2. Получить коммит, сохранить локальный Caddyfile.
3. Собрать backend и bot. Выполнить миграцию прежде, чем перезапускать процессы на новой версии:

```bash
docker compose build backend bot
docker compose run --rm --no-deps backend alembic upgrade head
docker compose run --rm --no-deps backend alembic current
docker compose up -d --no-deps --wait backend
docker compose up -d --no-deps bot
```

Ожидаемый head: `c93f821a70d4`. Миграция добавляет только четыре таблицы; цены и действующие подписки не меняются. PAYMENT_MODE не менять до активации магазина Robokassa. Тестовая оплата не увеличивает денежный баланс.

## Очередь выплат

```bash
docker compose exec -T backend python -m app.cli.referrals list
```

После согласования получателя, реквизитов и необходимых документов перевести заявку в processing **до** банковского перевода. Это блокирует её отмену пользователем:

```bash
docker compose exec -T backend python -m app.cli.referrals withdrawal REQUEST_UUID processing
```

Перед фактическим переводом повторно проверить текущую заявку, сумму и изменения после возвратов. Выполнить перевод отдельно через банк. Только после подтверждения банком отметить paid и указать уникальный номер банковской операции (без номера карты). Повтор команды с тем же номером не списывает баланс снова:

```bash
docker compose exec -T backend python -m app.cli.referrals withdrawal REQUEST_UUID paid --reference BANK_TRANSFER_ID
```

Не делать повторный банковский перевод, если первый уже выполнен, а команда подтверждения завершилась ошибкой. Сначала выяснить состояние операции и заявки. Нельзя обозначать paid до реального перевода. Удержания/оформление выплаты проверяются отдельно, команда не рассчитывает налоги.

Отказ возвращает резерв в доступный баланс; комментарий увидит участник:

```bash
docker compose exec -T backend python -m app.cli.referrals withdrawal REQUEST_UUID rejected --note "Причина отказа"
```

## Корректировка после возврата покупки

Указывается **накопленная подтверждённая сумма возвратов** по исходному платежу, а не размер очередного частичного возврата. Например, после возврата 100 ₽, а затем 99 ₽ второй вызов должен содержать 199.00. Повтор той же суммы не списывает комиссию дважды:

```bash
docker compose exec -T backend python -m app.cli.referrals refund PAYMENT_ID --total-rub 100.00
docker compose exec -T backend python -m app.cli.referrals refund PAYMENT_ID --total-rub 199.00
```

## Откат

Не удалять новые финансовые таблицы. Миграция намеренно запрещает downgrade с потерей истории. При необходимости остановить операции выплат, сохранить БД и вернуть предыдущий код; накопленная история останется в таблицах.
