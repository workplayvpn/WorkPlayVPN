# Work&PlayVPN: синхронизация бота и Mini App

База обновления: d211483. Изменения backend и бота необходимо развёртывать вместе, сначала backend, затем бот. Миграция базы не нужна.

## Поведение

- Общий селектор каталога для бота и Mini App. Mobile показывается только пользователям, допущенным действующей настройкой mobile_pilot_user_ids; пилот не расширяется.
- Каталог сначала предлагает Basic/Mobile, затем сроки выбранной подписки. При подтверждении оплаты показывается тип подписки. Старые кнопки проверяются по текущему доступному каталогу перед созданием платежа.
- Список подписок показывает независимые сроки и общий лимит устройств. Подписка открывает свои действия, продление, ключ и QR-код. Mobile-only не получает кнопку Basic. Старые subscription_key/subscription_qr открывают выбор подписки.
- QR-коды кодируют соответствующую ссылку subscription_url или mobile_subscription_url. Это ссылки подписок для импорта в Happ; QR не содержит ссылки на оплату.
- Ссылки инструкций устройства используют тот же персональный путь Basic и, при доступном auto-пилоте, Mobile, что Mini App. Старое отображение необработанного access_key убрано.
- Устройства в боте отображаются как модель Happ (ОС); запасной вариант — ранее сохранённое имя. Публичный ID показывается отдельно. Источник данных тот же, что Mini App.
- Смена региона в боте теперь применяется ко всему аккаунту через тот же сервис, что Mini App. Старые кнопки регионов также выполняют изменение для всего аккаунта. Недоступные регионы только показывают уведомление. Страны: NL, DE, RU, FI.
- Синие действия в каждом меню стоят первыми; порядок внутри групп сохраняется. Кнопка рефералов открывает view=referrals в Mini App. Программа пока остаётся экраном «скоро» без обещания несуществующих бонусов.
- Разделы получают собственные PNG-обложки. После QR следующая операция меняет изображение на обложку нового раздела. Длинный текст выводится отдельным сообщением, чтобы не превышать лимит подписи Telegram.
- Отображаемый бренд сайта, фавиконов, оплаты, серверов и профилей Happ — Work&PlayVPN. Домены, имена файлов, ключи настроек, пути, технические node.code и прежняя история миграций сохраняются.

## Изображения

- bot/assets/avatar.png — новый аватар; исходное изображение создано ImageGen: графит, большая W, бирюзовая орбита, янтарный спутник. Использован встроенный режим генерации.
- bot/assets/description.png — изображение описания до запуска, 640×360.
- bot/assets/welcome.png — главный экран после /start.
- bot/assets/screens/*.png — воспроизводимые графические обложки разделов с точными русскими надписями и стилем Mini App.

Аватар: BotFather → /setuserpic → выбрать бота → отправить avatar.png как фотографию.
Картинка описания: BotFather → /mybots → выбрать бота → Edit Bot → Edit Description Picture → отправить description.png. Это настройки Telegram, не файлы работающего контейнера.

## Проверки

Локально выполнено: 13 offline unittest бота, 15 unit-проверок ссылок/профилей backend, импорт backend, отказ без авторизации для новых внутренних маршрутов. Полная PostgreSQL suite здесь не запускалась.

В PowerShell после распаковки:

```powershell
docker compose --profile testing run --rm tests
if ($LASTEXITCODE -ne 0) { throw "Backend tests failed" }
docker compose run --build --rm --no-deps --entrypoint python bot -m unittest discover -s tests -v
if ($LASTEXITCODE -ne 0) { throw "Bot tests failed" }
git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw "Diff check failed" }
```

После коммита и push на сервере: git pull --ff-only; docker compose up -d --no-deps --build backend bot; docker compose ps backend bot; docker compose logs --tail=50 backend bot. Caddy использует монтируемые файлы сайта; проверить бренд страницы после обновления. Сохранить локальный блок bot-forma.ru в Caddyfile.

Ручная проверка после развёртывания: /start → каталог → Basic/Mobile → сроки; подписки → выбранная подписка → ключ и QR; устройства; смена региона; рефералы; возврат с QR на главную. Реальный платёж без отдельной проверки режима эквайринга не нужен.
