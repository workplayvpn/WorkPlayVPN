# HAPP Smart Routing

WorkPlayVPN can attach a versioned HAPP routing profile to selected users'
subscription feeds.

The first rollout keeps the VPN enabled while routing Russian services
directly:

- `geosite:category-ru` -> direct;
- `geoip:ru` -> direct;
- private and local networks -> direct;
- all unmatched traffic -> the selected VPN proxy.

The routing profile is generated by
`app.services.happ_smart_routing` and delivered as a
`happ://routing/onadd/...` line in the decoded HAPP subscription body. HAPP
binds that profile to the subscription. Generic and Hiddify feeds are not
changed.

## Rollout

`HAPP_SMART_ROUTING_USER_IDS` controls who receives the profile:

- empty - disabled for everyone (default);
- `1` - enabled only for user 1;
- `1,33` - enabled for users 1 and 33;
- `*` - enabled for every HAPP subscriber.

Start with one canary user. Do not use `*` until banking, marketplace,
government-service, DNS, and ordinary proxy traffic have been tested on the
supported HAPP platforms.

## Updating rules

When the profile changes, increase `HAPP_SMART_ROUTING_VERSION` to a newer Unix
timestamp. HAPP uses `LastUpdated` to recognize and apply the newer profile.

The configured GeoIP and GeoSite sources are downloaded by HAPP. The routing
profile must remain disabled if those sources are unavailable or incompatible
with a supported client version.
