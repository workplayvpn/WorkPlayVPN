# Блокировка удалённого устройства и превышения лимита

Исправление устанавливается поверх патча WorkPlayVPN-happ-auto-enrollment-2026-10-04.zip и отменяет автоматический возврат удалённых HWID. Общие ключи Basic/Mobile и новый автоматический импорт ранее неизвестных устройств сохраняются.

## Итоговое поведение

- Новая установка Happ с X-HWID автоматически занимает свободный общий слот.
- Повторное обновление зарегистрированной установки не создаёт ещё один слот.
- Удаление устройства отзывает его Basic и Mobile VPN-данные через существующий сервис удаления. Устройство общее для обеих подписок.
- Удалённый HWID по общей ссылке больше не регистрируется автоматически. Появление свободного слота или покупка дополнительных слотов не отменяют удаление.
- При обновлении удалённому HWID выдаётся профиль «Устройство заблокировано» с объявлением причины и только blackhole outbound. Никаких действующих VPN-данных этот ответ не содержит.
- При заполненном лимите новый HWID получает информационный профиль «Превышен лимит устройств» с подсказкой: «Либо удалите устройство из списка, либо докупите слоты». Устройство не добавляется в список и не получает рабочие VPN-данные. После освобождения/покупки слота этот новый HWID может обновить профиль и зарегистрироваться.
- Устройства, уже зарегистрированные и не удалённые, продолжают работать при заполненном лимите.

Блокировка доступа не означает удаление локальной записи профиля из Happ. Наш сервер не управляет кнопкой включения VPN в чужом приложении: при информационном профиле кнопка может оставаться активной, но ответ не содержит рабочего VPN-сервера. Внешний вид объявления и принятие JSON-профиля должны быть проверены на реальной версии Happ.

Нативный отказ Happ при добавлении сверх лимита существует у сервиса Happ Limited Links через InstallID и проверку check.happ-proxy.com. Этот патч его не подключает: он обеспечивает серверный контроль собственного списка устройств и отдаёт сообщение через announce. Документация: https://docs.happ-proxy.com/getting-started/quickstart .

Уже открытое соединение может сохраняться до закрытия сессии; отзыв серверного UUID и обновление клиентского профиля не являются командой мгновенного отключения туннеля на телефоне. Если после удаления и повторного отключения/включения VPN старый профиль всё ещё даёт интернет, нужна отдельная диагностика фактического UUID на ноде. Серверный отказ от автоматической выдачи нового UUID исправлен здесь.

## Windows: тестирование

В корне проекта:

```powershell
$ErrorActionPreference = "Stop"
Expand-Archive -LiteralPath .\WorkPlayVPN-happ-device-blocking-2026-10-05.zip -DestinationPath . -Force -ErrorAction Stop
$backendSource = Join-Path (Get-Location).Path "backend"
$opsSource = Join-Path (Get-Location).Path "ops"
docker compose --profile testing run --rm --pull never --volume "${backendSource}:/app:ro" --volume "${opsSource}:/ops:ro" tests
if ($LASTEXITCODE -ne 0) { throw "Тесты backend не прошли" }
git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw "Проверка изменений не прошла" }
```

Локально: 55 тестов прошли, 2 PostgreSQL-теста конкурентной регистрации пропущены. Их проверяет контейнер с тестовой PostgreSQL. Полный набор тестов запускать перед отправкой.


## Проверка исправления

Ваш iPhone 14 Pro Max уже вернулся в активный список из-за предыдущего режима. После установки этого исправления удалите актуальную запись iPhone ещё раз.

1. На iPhone отключите VPN, обновите профиль Basic. Должно появиться сообщение о блокировке; телефон не должен вернуться в кабинет.
2. Снова обновите Basic несколько раз, затем Mobile на том же телефоне. Телефон не возвращается, рабочие VPN-данные не выдаются. Проверяйте именно доступ через этот профиль: другая активная VPN-подписка может продолжать работать.
3. На другом, не удалённом устройстве проверьте, что VPN работает.
4. При заполненном лимите импортируйте общий ключ на новом тестовом устройстве. Проверьте сообщение о лимите, отсутствие доступа и неизменный счётчик устройств.
5. Освободите/купите слот и обновите профиль нового устройства: оно регистрируется и получает доступ. Намеренно удалённый HWID при этом остаётся заблокированным.

Для осознанного возврата удалённого HWID остаётся ранее существовавший путь: создать новую запись устройства в личном кабинете и использовать её индивидуальную ссылку инструкции/активации. Общая ссылка и фоновое обновление не разрешают возврат. Кнопка самостоятельного снятия блокировки в рамках этого патча не добавляется.

HWID сообщается клиентом и не является аппаратной аттестацией. Полный запрет обхода через подмену HWID или ранее скопированный сырой VLESS этот механизм не обеспечивает.
