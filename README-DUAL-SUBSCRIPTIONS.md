# WorkPlayVPN: Basic и Mobile одновременно

Пакет распаковывается в корень проекта поверх коммита, из которого был
создан `WorkPlayVPN-latest.zip` 26.09.2026. Он содержит только изменённые
исходники и этот файл. Секретов и `.env` внутри нет.

## Поведение

- Покупка другого типа тарифа создаёт отдельную активную подписку с собственным
  сроком. Повторная покупка того же типа продлевает только её. Уже оплаченные
  дни Basic при покупке Mobile сохраняются.
- Бесплатный триал при первой покупке Mobile по-прежнему переходит на Mobile
  с сохранением оставшегося времени триала.
- Общий список устройств и Direct остаются общими. Лимит устройств равен
  большему из лимитов активных тарифов плюс купленные дополнительные места;
  он не удваивается.
- Истечение Mobile при действующем Basic снимает только CDN-доступ. Истечение
  Basic при действующем Mobile сохраняет Direct для профиля Wi-Fi. После
  окончания последнего тарифа снимается весь доступ.
- Прежний трёхчастный ключ и ссылка `/sub/...` действуют только для Basic.
  Mobile получает отдельный подписанный четырёхчастный ключ. Mini App и бот
  показывают две ссылки при двух активных подписках.
- Пилотное ограничение Mobile и тестовый режим оплаты остаются в силе.

## Проверка перед развёртыванием

1. Распаковать архив в корень проекта. Не коммитить и не отправлять на сервер,
   пока не пройдут локальные проверки.
2. Проверить список изменений и синтаксис:

   ```powershell
   git status --short
   git -c core.whitespace=cr-at-eol diff --check
   .\.venv\Scripts\python.exe -m compileall -q backend\app bot
   node --check caddy\mini-app\assets\app.js
   ```

3. На **отдельной** тестовой PostgreSQL-базе `workplayvpn_test`, после
   `alembic upgrade head`, запустить из каталога `backend`:

   ```powershell
   ..\.venv\Scripts\python.exe -m pytest -q tests/test_dual_subscription_tiers.py tests/test_trial_to_mobile_upgrade.py tests/test_happ_client_profile.py tests/test_subscription_feed_metadata.py
   ..\.venv\Scripts\python.exe -m pytest -q
   ```

   В этом пакете нет миграции: `plans.access_tier` и Mobile-поля устройства
   уже есть в исходном коммите. Не запускать тесты на рабочей базе.

4. После локальных тестов проверять тестовую покупку аккаунта пилота: Basic →
   Mobile, затем обе ссылки Happ и оба срока в Mini App. Не использовать
   настоящую карту в тестовом режиме Robokassa.

Здесь проверены восемь сценариев покупки/истечения/разделения ссылок на
локальной SQLite-схеме, существующий переход с триала (с учётом того, что
SQLite не сохраняет часовой пояс), 25 независимых тестов профилей и
метаданных Happ, импорт backend, компиляция Python и синтаксис JavaScript.
Полный набор тестов на PostgreSQL должен быть выполнен перед выпуском.

После первого полного запуска исправлены обработка просроченных тарифов при
запросах на активацию устройства, отсутствие значения времени активации и
ожидания старых тестов к расширенному API. Повторный полный прогон на
PostgreSQL обязателен для этого обновлённого архива.
